# G1-03 · CI en GitHub Actions

## Objetivo

Un workflow que, en cada push y PR, ejecute las tres puertas
(`cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`,
`cargo fmt --all --check`) sobre Rust estable, de modo que un PR rojo no llegue
a main.

## Alcance

**Haz**
- Rama `feat/g1-03-ci` desde el tip del stack.
- `.github/workflows/ci.yml` con: `push` a `main`/`develop` y `pull_request`;
  `actions/checkout`, `dtolnay/rust-toolchain@stable`, `Swatinem/rust-cache`;
  jobs `test`, `clippy`, `fmt` (uno por puerta, para lectura rápida del fallo).
- Probar el workflow con un PR de la propia rama: los tres jobs en verde.

**No hagas**
- No añadas pasos que no sean las tres puertas (build de release, docs, coverage:
  después).
- No uses `continue-on-error` salvo en un paso cuya imposibilidad quede
  documentada en el propio yml.

### Archivos previstos
- `.github/workflows/ci.yml` — nuevo — las tres puertas por push/PR.

## Criterios de aceptación
1. Workflow commiteado en la rama y visible en GitHub.
2. PR de prueba con los tres jobs en verde sobre código real.
3. Un commit que rompa un test deja el job `test` en rojo (probado una vez,
  revertido acto seguido).

## Verificación
El propio PR de prueba · `git status` limpio.

## Coste y riesgo
Coste: M (incluye la ida y vuelta del PR de prueba). Riesgo: bajo; el runner
de GitHub Actions corre Rust estable sin dependencias del sistema.
